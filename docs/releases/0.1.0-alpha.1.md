# PPTX Compiler 0.1.0-alpha.1

> **Status: draft — not released.** There is no release tag, npm publication,
> or published package artifact for this version.

## Purpose and boundary

This candidate alpha demonstrates one trustworthy, installed path from a
repository-owned synthetic POTX project to a native DrawingML card-arrow
candidate PPTX with a replayable build record and honest blocked QA. It is intended for
evaluating the contracts, failure behavior, package boundary, and contributor
workflow—not for general presentation production.

The public path does not yet provide the PowerPoint compatibility evidence
needed to claim editability or delivery readiness.

It is not arbitrary-template compatibility, a general renderer, delivery
approval, or a claim that any support row is `supported`.

## Fact ownership

The source template owns unchanged inherited content. The project JSON data and
`DeckSpec` own authored meaning. `SlideLayoutIR` owns editable constraints;
`ComposedSlidePlan` owns resolved geometry. `CandidateBuildRecord` binds both to
the exact candidate bytes. `QaReport` records the assessment, and only a later
passing final-delivery boundary could create `BuildArtifact`.

The support matrix owns claim status, the package plan owns intended tarball
contents, and the release gates own publication eligibility. This draft note is
only a projection of those authorities.

## What the candidate contains

The planned release graph has four packages:

- `pptx-compiler`: the explicit-root CLI;
- `pptx-compiler-core`: contracts, secure ingestion, dispatch, candidate
  assembly, replay, and QA foundations;
- `pptx-compiler-native-card-arrow`: the exact native DrawingML capability;
- `pptx-compiler-public-synthetic`: the repository-owned conformance project.

The workspace root remains private. Every leaf manifest is also still private,
and npm publication remains blocked pending separate authorization.

## Candidate flow

The installed smoke path is:

```text
init public-synthetic project
  -> inspect exact bounded POTX
  -> validate complete project graph and experimental support closure
  -> render one native-card candidate and CandidateBuildRecord
  -> qa re-derives and compares both artifacts
  -> decision: blocked; no BuildArtifact
```

The renderer requires explicit experimental opt-in. It derives placement from a
semantic slot, preserves source bytes, verifies containment and collateral
diff, writes the record before the PPTX logical commit marker, and never turns
the candidate into a delivery merely because assembly succeeds.

## Executable contracts

- JSON Schema is normative for project, template, capability, deck, candidate,
  QA, and build records; generated TypeScript declarations are checked public
  consumers.
- Unknown versions, fields, inputs, features, relationships, semantic bindings,
  platforms, and evidence fail closed.
- The exact capability registration binds metadata, executor, schemas,
  conformance cases, and QA assertions before any invocation can run.
- Candidate generation and QA use the same pure layout derivation and compare
  the complete intent, plan, package diff, record, and PPTX bytes.
- Publication failures expose not-committed, rollback-incomplete, or
  commit-uncertain states instead of hiding ambiguity.

## Limitations

The authoritative user-facing list is
[`docs/KNOWN_LIMITATIONS.md`](../KNOWN_LIMITATIONS.md). The release-critical
limits are:

- only the fixed public-synthetic POTX/native-card candidate profile is exposed;
- QA is intentionally blocked and produces no `BuildArtifact`;
- PPTX input, arbitrary POTX, formula delivery, asset placement, charts, tables,
  media, animations, notes, and comments are outside scope;
- desktop PowerPoint and real Pandoc are not public-CI dependencies;
- Windows has no sudden-power-loss directory-entry persistence claim;
- no npm package, release tag, signing/provenance record, or published-artifact
  equality exists.

## Reproduction

Follow [`docs/REPRODUCIBILITY.md`](../REPRODUCIBILITY.md) from a clean checkout
with Node.js 22.x or 24.x and its bundled npm. The expected installed smoke
result is blocked QA and no `BuildArtifact`. Generated fixtures, tarballs,
smoke projects, decks, renders, and raw reviews remain ignored.
